Technical completion and editorial satisfaction are separate: the current 30-second intro is a private workflow sample, not an approved promotional example.

Environment: macOS 14.6.1 arm64, Node.js 22.16.0, Python 3.9.6, Apple Swift 6.0.3. The release source version is 0.5.0. The production bridge reported 0.5.0-dev.1; the original attempt began after an idle/saved restart onto 0.4.2. Neither is mislabeled as a fresh 0.5.0 production run. Chrome login was preserved.

The new AIX task first returned Agent code 300. A later native-history lookup recovered its exact original request and unsubmitted card. Recovery pins separate history and original-response hashes, retaining code 300 and one attempt. The live Vue build lacked direct DOM component pointers and exposed a wrapped source getter; the adapter now identifies the exact vnode owner and bounded read-only getter dependency sequence. Markdown line breaks remain part of exact task identity. Model, workflow, original task, reference asset, count, prompt, ratio and resolution checks all passed before generation.

The first submitted image was correctly accepted with every request-parameter check true, but MCP's string HTTP status "200" triggered the old number-only check. Synthetic comparison reproduced the false block against sealed 0.4.2. Exact number/string compatibility and a narrowly scoped, locked reconciliation retain the original ledger and network bytes. False parameter acknowledgements, missing bodies, changed hashes and other block reasons still cannot pass. After a bridge restart, one image notification was absent from the new network buffer; the already decoded image was retained and the same task resumed. Completion then verified backend status, saved/reopened canvas, reference connections and local hashes. The original image request and generation were never repeated.

The downloaded AIX video has 121 decoded frames at 24fps, a 5.042-second video track and a 5.054-second container. Its correct five-second submission and native duration drift are recorded separately; no original media was trimmed or regenerated to make this field pass.

Independent edge-tts 7.2.8 with Xiaoxiao Mandarin produced a short sample and six narration segments at normal speed. Original MP3s and word timing were retained; editing uses 48 kHz PCM16 WAV. The extracted caption module reproduced the actual six-cue SRT byte for byte without synthesizing audio or calling AIX. Source timing, complete decoding, waveform and local ASR assist review. The assistant cannot directly hear audio input in this session; subjective listening quality is not claimed.

Resolve required recorded local corrections: a Fusion composition had not finished committing, and the first exported WAV routing was left-only. The retained second native render is centered stereo: both channel RMS values are about -23.43 dBFS, peak about -6.50 dBFS, zero clipped samples, final speech activity near 28.33 seconds, and source/export envelope cosine similarity above 0.9999. The video track is exactly 30.000 seconds / 720 frames. AAC audio duration is 30.080078 seconds; FFmpeg and browser report about 30.080 seconds, while AVFoundation reports a 30.000-second container. This is codec padding, not truncated voice.

The existing exported intro was played to its end, fully decoded, and inspected at boundaries/key frames with privacy pixel checks. Its project was saved, closed and reopened, verifying 53 editable text elements plus video/audio/media hashes. The newly completed AIX task was not substituted into this sample: the user redirected work to extracting and releasing the workflow before that editorial revision. Thus AIX generation and voiced editing are separately verified stages, not a claim that this new job is already inside the sample movie.

During development, an attempt to run the full Node suite in the active production directory had two expected project-lock collisions; no real task state was bypassed or overwritten. The suite passed after the real task finished and in the isolated clean directory. Preserved logs distinguish those intermediate failures from final passing runs. The original case-media hashes and all earlier release inventories are checked by the companion preservation report. All public files, ZIP membership/hashes/CRC/metadata and independent Git history are audited before publication.

Two recovery defects were found during validation. An unconditional reload caused a renderer crash during completed-job verification; normal reconciliation now reopens through native canvas history. A restarted bridge had no cached chat requests, and nested polling caused a timeout; recovery now checks the cache once and observes fresh requests through native history controls with one retry layer. Both cases retained the completed ledger and did not submit new generations. The final restart check passed after these changes.

The first development-time canvas creation also exposed an initialization race. The final implementation waits for a nonempty new identity before naming the canvas, and refuses to adopt another canvas if an interrupted attempt never recorded its new identity. A subsequent fresh creation and repeated-create check passed.

Release packaging uses 43 allowlisted source files plus a generated hash manifest. Account bindings, job configurations and ledgers, prompts from real jobs, logs, screenshots, generated media, dependencies, compiled binaries and original Git history are excluded. Content scanning, archive entry/hash/metadata inspection and the new Git history audit are recorded in the release's companion audit files. Runtime validation evidence stays private.

Strict whole-second duration did **not** pass: the original video was retained without trimming or transcoding. Universal crash recovery, creative accuracy for arbitrary prompts, Windows/Linux, other model combinations, batch generation and team-canvas administration are not claimed.
