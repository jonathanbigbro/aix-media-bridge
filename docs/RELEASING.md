# Release procedure

1. Run `npm run setup`, `npm run test:all`, `npm run doctor` and `npm run edit -- doctor` in a clean source directory. The last check needs an already running Resolve instance. A stable production claim for changed browser interactions needs live validation. When paid generation is outside the authorized scope, ship only a preview and explicitly record the unverified production path; packaging alone does not authorize extra generation.
2. Update the version, skill, validation record and `scripts/release-files.json` together.
3. Run `npm run release`. The builder uses only the explicit allowlist, refuses symlinks, scans text, checks approved media hashes, writes a hash manifest and creates a zip with anonymous archive ownership metadata. An existing version directory or ZIP is never overwritten.
4. Run `npm run audit -- dist/aix-media-bridge-0.5.0` and `npm run audit:archive -- dist/aix-media-bridge-0.5.0.zip --directory dist/aix-media-bridge-0.5.0` (replace the version for a future release). Inspect a fresh extraction and check it against the same manifest. Review findings; do not silently replace suspected credentials with placeholders and continue.
5. If preparing GitHub source, initialize a new repository from the audited release files. Do not copy the research repository's `.git` directory or push its existing history. Stage only the files in `release-files-manifest.json`, plus that manifest.
6. Audit the new Git history and staged tree before any push. Runtime files, local account bindings, private prompts, screenshots, raw or unreviewed generated media, native projects, local paths and historical evidence must remain excluded. Only exact media bytes pinned in `scripts/release-media.json`, with matching review records, may ship as examples. New or changed media requires visual and metadata review before updating the registry. A scanner passing records the checks performed; it does not identify every possible private visual detail or secret format.

GitHub repository selection and publication are separate from the local build. The build does not create a remote, push, upload media or change sharing settings.

For 0.4.1, retain a before/after byte inventory of every 0.4.0 release file (including its independent Git objects) and the four approved case media. Install from the unchanged dependency lock entries with Node.js >=22.12.0. Record sourceVersion separately from the already running bridge version. Retain failing synthetic regression evidence privately; do not ship test logs, bindings or local paths.

For 0.4.2, preserve both 0.4.0 and 0.4.1 distributions, their checksums, companion reports and independent histories. Run the original 50 tests plus deterministic concurrency regressions in the development and clean-source directories. The synthetic daemon dispatcher and separate writer process are local tests, not a new live bridge. Status must remain local and read-only even when diagnostics fail.

For 0.5.0, preserve 0.4.0, 0.4.1 and 0.4.2 archives, reports and histories. Include independent narration/caption modules, narrated Resolve support and their explicit allowlist entries. Record same-machine AIX production and Resolve validation separately, including the development bridge version and recovery interventions. Do not publish the unapproved intro sample, raw narration, DRP, configs or production evidence. Public source uses the four existing reviewed case files unchanged.
