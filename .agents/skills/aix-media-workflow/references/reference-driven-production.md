# 参考视频、多模态输入与恢复经验

## 先拆角色，再准备引用

将素材职责写进配置或镜头清单：产品图约束身份和结构，风格图约束材质/灯光/场景，白模视频约束运动、接触和运镜。不要让粗糙白模同时成为最终外观标准。图像引用的顺序、槽位和数量属于生成参数，需要与实际提交请求逐项核对。

需要白模时使用同包的 [Blender 技能](../../blender-reference-blockout/SKILL.md)，先验证目标主体轮廓、永久部件身份、附件绑定与时间采样，再生成运动参考。需要审美方案时先组织可比较的视觉方向；用户选定后保持身份参考，避免每个镜头重新设计主体。

## 能力门槛和验证层级

本发行版的公开 `media-run.mjs` 仍是 schema 2：一张 PNG、横屏、固定模型组合。不要把竖屏、多图、视频引用或更长时长写进 schema 2，删参数过校验也不正确。

同机开发中曾通过独立原生卡片流程完成竖屏、多图、运动视频引用和较长视频，但这些实验性适配器没有作为本版公共生成 CLI 发布。需要这些规格时先查看当前原生工作流能力，再使用已安装且经过核验的适配器或原生 UI；不要声称本包有不存在的命令。增加公共适配器之前，应有独立配置校验、引用映射、提交一次性记录和完整下载恢复测试。

每次都从当前工作流读取支持的比例、时长、分辨率、引用种类/数量/槽位；版本变化时重新核验。对本地输入检查 MIME、宽高、总像素、字节大小、FPS、时长和完整解码。像素限制与文件大小限制不是同一个条件。某次后端拒绝暴露的阈值只是当时证据，不应写死为通用模型能力。

## 异常处理

- 超时、桥断连、漏通知、HTTP 非 JSON 响应不证明任务没提交。先核对原节点、任务状态、请求证据和本地账本。
- 只有明确终态失败且没有产物，才讨论修改输入后的新尝试；记录原 job、失败证据、修改原因与后继 job 的关系。未知/运行中状态不能通过换 ID 绕过。
- 不改已开始任务的配置或参考文件。合法输入确需修订时保留原任务，沿用用户已有授权判断是否可以重试；付费重试的次数/成本超出授权则停下说明。
- 上传/下载按内容哈希认领，检查本机已有同哈希文件。一次原生下载后迟迟未找到文件时先核对下载目录与完成状态，不重复点下载。
- 网络状态码的数字/字符串表示可兼容，但不能放宽真正的参数不匹配。零报价或不可用报价不能据此宣称免费。
- 区分源码版本与实际运行桥版本。线上操作验收记录实际版本；打包通过不等于新版桥完成过真实生成。

## 生成之后

保留原片，记录容器、视频轨、浏览器时长和完整解码帧数。生成合规、画面质量、动作连续性、剪辑效果和声音听感分别验收。

生成细节变化不应一律归因于白模不精细：分开检查几何与相机、动画采样、生成时序、编码和后期变速。只有发现对应原因才修改该层。

用户要求混剪、缩短片尾、调整 Logo 或补音效时，优先使用已下载素材完成后期。未被请求的新视频生成不能代替剪辑工作。
