白模的交付目标是可验证的空间和运动关系。先确定参考视频、替换主体、输出比例和用户要求保留的镜头语言。保留用户指定的创作风格，不从一个项目推导固定题材、动作或布景。

## 拆解与建立

1. 对原片记录尺寸、真实帧率、视频轨时长；制作全片联系表，再逐帧检查切点和关键接触。剪切、遮挡转场和连续运镜重新构图分开记录。采用从 0 开始、右端不包含的帧区间 `[in, out)`，不要直接用容器时长计算末帧。
2. 建立镜头表：原片范围、主体朝向与尺寸、摄影机高度/焦距/位置、前后景、遮挡顺序、接触/离地时刻。单目视频的深度和焦距可能多解；标注估计，优先让镜头内关系成立。
3. 使用目标产品多视图建立轮廓：长宽高、侧面剪影、底部体积、关键折面和识别性附件。细节按画面占比决定；远景不堆微细网格，近景不可只用不符合产品轮廓的方盒代替。
4. 定义世界坐标、主体局部坐标与永久部件 ID。通过对象/骨骼父级或约束固定附件，记录局部变换。镜头近侧不等于主体左侧；相机换边时不能重新解释部件身份。
5. 先用低采样渲染验证剪影、四边留白、支撑点、遮挡和运镜，再细化必要几何。最终给生成平台的运动参考应从场景重新渲染到合法尺寸。

建模和动画的具体取舍见 [references/model-and-motion.md](references/model-and-motion.md)。

## 动画与诊断

连续时间驱动动画，避免 `int(frame / divisor)` 或提前取整产生重复姿态。需要子帧时明确传入整数帧与小数子帧。一个完整动作至少包含预备、离地/移动、接触、承重/收束；节奏依据参考片和用户意图，不强制每个镜头都持续行走。

在整个时间线上检查实体绑定、接触、滑动和镜头换边；仅看首尾帧不能证明中间连续。发现抖动或变形时，先分辨白模空间错误、动画时间采样、编码重复帧、生成模型时序错误、后期变速。增加网格细节不能修复时间采样问题。

可用 FFmpeg 提取诊断帧，再运行脚本；PGM 是灰度检测副本，不替代原片视觉审阅：

```sh
mkdir REVIEW
ffmpeg -i INPUT.mp4 -vf scale=160:-2,format=gray -fps_mode passthrough REVIEW/frame-%06d.pgm
python3 scripts/audit_cadence.py REVIEW --fps 24 --out REVIEW/cadence.json
```

以上脚本路径相对本技能目录；使用一个新建的空 REVIEW 目录，帧率改为实际值。脚本检查重复帧、差分和交替停帧倾向，结果只是诊断线索。静态片尾、动作停顿和相机静止需要按镜头语义判断；无重复帧不证明步态自然。

交付 `.blend`、镜头表、坐标/部件绑定说明、白模视频及质量记录。给 AIX 的图像参考负责身份与材质，白模视频负责运动和空间，提示词明确两者职责。此技能本身不授权在外部平台生成或发布。
